# Переезд на новую систему

Что делать, если машину, на которой жил проект, сносят.

Код, сборка и выпуск релизов уже полностью на GitHub — их переносить не нужно. Незаменимого на
диске всего три вещи, и одна из них — ваши личные данные.

---

## 1. Данные приложения — сначала это

Life OS хранит всё **только на устройстве**. Снос системы уничтожает единственную копию: ни у
сервера, ни у разработчика её нет.

**Десктоп (Windows).** Откройте Life OS → **Настройки** → **Сохранить копию всех данных**, задайте
пароль (копия содержит номера документов и медицинские записи) и положите файл туда, что переживёт
переустановку: внешний диск, телефон, облако.

**Android.** Данные на телефоне снос компьютера не затрагивает, но копию всё равно стоит сделать —
телефон теряется отдельно от компьютера.

Копия и десктопа, и телефона — это один и тот же формат: файл, снятый где угодно, разворачивается
где угодно.

> **Копию нельзя класть в этот репозиторий.** Он публичный. Резервная копия — это ваши документы,
> суммы и медицинские записи; в репозитории им не место ни в каком виде, даже зашифрованными.

Сырые данные десктопа лежат в `%LOCALAPPDATA%\com.lifeos.app` (WebView2 держит там IndexedDB).
Скопировать эту папку целиком можно как подстраховку, но восстановление из неё держится на том, что
идентификатор приложения не менялся; штатный путь — файл резервной копии.

После переустановки: поставить Life OS из [релизов](https://github.com/Lucky2356/lifeOS/releases),
Настройки → **Восстановить из файла**. Если импортируете не тот файл — семь дней доступна отмена
(«Данные восстановлены из копии · Отменить»).

## 2. Ключи подписи — второе по важности

Оба лежат вне git намеренно и **нигде больше не существуют в читаемом виде**: в секретах GitHub они
есть, но прочитать их оттуда назад нельзя, только перезаписать.

| Файл                                 | Зачем                                  | Что будет, если потерять                                                   |
| ------------------------------------ | -------------------------------------- | -------------------------------------------------------------------------- |
| `C:\Development\life-os-release.jks` | подпись Android-релиза + пароли к нему | пока секрет в GitHub цел — сборки идут; но восстановить его будет неоткуда |
| `apps/desktop/lifeos-updater.key`    | подпись авто-обновлений десктопа       | то же: пока секрет цел, обновления подписываются                           |

Сборкам эти файлы не нужны — они читают секреты GitHub. Опасен другой сценарий: секрет придётся
пересоздать (перенос в другой репозиторий, компрометация, чистка). Без исходного keystore подписать
APK тем же ключом станет нечем, а **Android не ставит обновление поверх приложения с другой
подписью** — придётся удалять приложение, теряя все данные.

Поэтому: `.jks`, его четыре пароля (keystore, alias, key) и `lifeos-updater.key` — в менеджер
паролей или на носитель, который переживёт переустановку. Не в репозиторий.

Что уже в секретах GitHub (значения не читаются, только имена):
`ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`,
`TAURI_SIGNING_PRIVATE_KEY`.

## 3. Незапушенное

```bash
git status --short          # пусто = всё сохранено
git log origin/main..HEAD   # пусто = всё запушено
```

Переносить **не нужно**: `node_modules`, `apps/*/dist`, `src-tauri/target`, `android/build`,
`android/app/build` — всё это восстанавливается одной командой и занимает гигабайты.

## Как работать дальше без тяжёлой локальной машины

### Правки и тесты — GitHub Codespaces

Репозиторий → **Code** → вкладка **Codespaces** → **Create codespace on main**. Открывается
VS Code в браузере с уже настроенной средой (`.devcontainer/devcontainer.json`): Node 22 той же
версии, что в CI, зависимости ставятся сами, ESLint и Prettier включены.

```bash
pnpm test          # тесты
pnpm dev           # dev-сервер, порт 5173 пробрасывается сам
pnpm lint && pnpm typecheck
```

Личный аккаунт GitHub даёт бесплатную квоту в месяц; неиспользуемый codespace засыпает через 30 минут
и перестаёт её тратить, а через 30 дней бездействия удаляется — код при этом остаётся в репозитории,
пока он запушен.

Для мелкой правки codespace не нужен вовсе: клавиша <kbd>.</kbd> в репозитории открывает веб-редактор
(без терминала и тестов — только текст).

### Выпуск релиза — из браузера

**Actions** → **Release** → **Run workflow** → ввести версию (`1.5.0`, без `v`) → **Run**.

Workflow сам: прогонит гейты (lint, форматирование, типы, тесты, контент), проставит версию во все
файлы, закоммитит, поставит тег и соберёт установщики — Windows `.exe`/`.msi` и подписанный Android
`.apk`, — приложив их к релизу вместе с манифестами авто-обновления.

Галочка **«Только проверка»** прогоняет всё то же самое, но ничего не коммитит и не выпускает —
удобно убедиться, что сборка зелёная, до настоящего выпуска.

Прежний путь тоже работает: `git push origin v1.5.0` с машины запускает ту же сборку.

### Что осталось только для машины

Ничего обязательного. Локально имеет смысл держать разве что установленное приложение — чтобы
пользоваться им самому.

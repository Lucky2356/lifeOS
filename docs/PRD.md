# Life OS — Product Requirements Document (MVP)

> Статус: **черновик Фазы 0**, ожидает утверждения заказчиком.
> Дата: 2026-07-04. Версия: 0.1.

## 1. Одна фраза

Life OS — персональная и семейная «операционная система для жизни»: единый реестр данных о жизни человека, который в спокойном режиме держит порядок, а в кризис подсказывает конкретные следующие шаги. **ИИ — опциональный слой поверх системы, а не её фундамент.**

## 2. Решения Фазы 0 (утверждено заказчиком)

| Параметр                   | Решение                                                                             |
| -------------------------- | ----------------------------------------------------------------------------------- |
| Первый content pack        | Регион **РФ**                                                                       |
| Языки интерфейса на старте | **RU + EN** (движок i18n проверяется сразу)                                         |
| Масштаб на старте          | **Личный / до 100 пользователей**                                                   |
| Первый клиент              | **Web (PWA)** — offline-first, устанавливаемый; desktop/mobile позже из общего кода |
| Первые сценарии контента   | Потеря работы, Смерть близкого, Продление документов, Переезд                       |

## 3. Пользовательские роли (RBAC)

- **Owner (владелец)** — полный контроль над своим контуром и домом, управление участниками, экспорт/удаление.
- **Adult (взрослый участник дома)** — доступ к общим данным дома по правам, свои приватные объекты.
- **Child / Restricted (ребёнок/ограниченный)** — урезанные права по умолчанию (принцип наименьших привилегий), видит только явно расшаренное.
- **Guest (гость)** — временный, ограниченный по времени и объёму доступ.

Авторизация — **row-level** (на каждый объект данных), не только на уровне эндпоинта.

## 4. Ключевые сценарии (user journeys)

### 4.1 Life Ledger (ядро) — MVP-приоритет №1

- Создать объект жизни (документ / вещь с гарантией / подписка / страховка / медицинская запись / фин. обязательство) с типом, сроком/дедлайном, статусом, вложениями (сканы/фото), историей.
- Получить напоминание о приближении дедлайна (истечение паспорта, конец гарантии, продление подписки) — **без ИИ**, по правилам.
- Просмотреть и отредактировать объект офлайн; синхронизация при возврате сети.
- Экспортировать все свои данные; удалить аккаунт и данные («право на забвение»).

### 4.2 Household OS (слой над ядром) — приоритет №2

- Создать «дом», пригласить участника с ролью.
- Расшарить объект/задачу на дом или конкретного участника с уровнем доступа.
- Общие бытовые задачи и обязанности (кто/что/когда), общие расходы и доли.
- Журнал доступа: кто и когда обращался к данным дома.

### 4.3 Decision Companion — приоритет №3

- Создать решение: критерии, веса, варианты, за/против → взвешенный итог.
- Записать принятое решение и позже — фактический исход.
- Видеть журнал прошлых решений и паттерны.
- Вызывается из любого модуля (сквозной инструмент).

### 4.4 Bureaucracy Autopilot — приоритет №4 (нужен content-pack-движок)

- Открыть гид (напр. «Продление паспорта РФ»): пошаговый чек-лист, нужные документы, дедлайны, статусы заявки.
- Гид подтягивает данные из Life Ledger (какие документы уже есть у пользователя).

### 4.5 Crisis Navigator — приоритет №5 (зависит от Ledger + движка)

- Выбрать плейбук («Потеря работы», «Смерть близкого», «Переезд»): чек-лист шагов + документы + куда обращаться.
- Плейбук привязан к данным пользователя (знает про его страховки/документы, подсказывает следующий шаг).
- Встраивает шаги Bureaucracy Autopilot внутрь себя.

## 5. Сквозной принцип «AI опционален»

- Глобальный тумблер ИИ + тумблер по каждому модулю в настройках.
- Любой сценарий выше выполним **вручную** (формы, чек-листы, поиск) при выключенном ИИ.
- Каждое ИИ-предложение имеет явный UI-маркер «предложил ИИ» и ручную альтернативу.
- ИИ — отдельный необязательный сервис, вызываемый по явному действию пользователя.

## 6. Нефункциональные требования

- **Offline-first**, near-real-time синхронизация, разрешение конфликтов.
- **Безопасность** (сквозная): MFA, шифрование at-rest/in-transit, row-level авторизация, аудит-логи, OWASP Top 10, безопасная загрузка файлов, SCA/secret-scanning в CI, threat model до кодирования Ledger/Household. См. `docs/SECURITY.md` (Фаза 1).
- **Доступность (a11y)**: контраст, скринридеры, масштаб текста, клавиатура.
- **Calm technology**: без стриков, бесконечных лент, навязчивых уведомлений.
- **i18n/l10n** и **content packs**: регион/язык — данные, не код.
- **Монетизация**: бесплатно; архитектурная точка под будущие донаты (billing вне core), без тёмных паттернов.

## 7. Границы MVP

**В MVP входит:** Life Ledger (полный вертикальный срез: CRUD → вложения → напоминания → offline-sync → шифрование), базовый Household OS (дом, роли, шаринг, аудит), Decision Companion, content-pack-движок + 4 сценария (РФ), i18n RU/EN, аутентификация с MFA, экспорт/удаление данных.

**Вне MVP (заложено архитектурно, реализуется позже):** desktop/mobile клиенты, реальная платёжная интеграция донатов, антивирус-сканирование загрузок (интерфейс — да, провайдер — заглушка), второй регион, ИИ-функции сверх минимального опционального слоя.

## 8. Критерии успеха MVP

1. Пользователь ведёт реестр объектов жизни и получает корректные напоминания **при выключенном ИИ**.
2. Приложение полноценно работает офлайн и корректно синхронизируется без потери данных / с предсказуемым разрешением конфликтов.
3. Семья из 2+ человек делит объекты/задачи с корректными правами (ребёнок не видит лишнего), есть журнал доступа.
4. Все 5 модулей ощущаются как одно приложение (цельная навигация), а не 5 разных.
5. Второй регион/язык можно добавить как content pack без правок кода ядра (доказано на RU/EN).
6. Пройдены базовые проверки безопасности (threat model, шифрование, row-level auth, CI-гейты SCA/secret-scan).

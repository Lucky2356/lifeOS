# Life OS — RBAC (роли и права доступа)

> Принцип: наименьшие привилегии по умолчанию. Авторизация на уровне каждого объекта (row-level),
> не только на уровне эндпоинта. Двойная защита: RLS в PostgreSQL + проверки в API-слое.

## Роли (в контуре household)

| Роль      | Описание               | По умолчанию                                                                            |
| --------- | ---------------------- | --------------------------------------------------------------------------------------- |
| **owner** | Владелец контура/дома  | Полный контроль: участники, шаринг, удаление дома, экспорт                              |
| **adult** | Взрослый участник      | Свои приватные объекты + расшаренные ему; создание общих задач/расходов                 |
| **child** | Ребёнок / ограниченный | Только явно расшаренное; урезанный набор действий; не видит чувствительное по умолчанию |
| **guest** | Гость (временный)      | Узкий доступ к явно выданным ресурсам, с `expires_at`; авто-отзыв                       |

## Матрица действий (упрощённо)

| Действие                         | owner |      adult      |      child      |      guest      |
| -------------------------------- | :---: | :-------------: | :-------------: | :-------------: |
| Управлять участниками/ролями     |  ✅   |       ❌        |       ❌        |       ❌        |
| Приглашать гостя                 |  ✅   |       ⚙️*       |       ❌        |       ❌        |
| Создавать свои объекты Ledger    |  ✅   |       ✅        |       ⚙️*       |       ❌        |
| Видеть общий объект              |  ✅   |    по share     |    по share     |    по share     |
| Редактировать общий объект       |  ✅   | по share (edit) | по share (edit) | по share (edit) |
| Управлять шарингом объекта       |  ✅   |   если manage   |       ❌        |       ❌        |
| Видеть журнал доступа (audit)    |  ✅   |       ✅        |       ❌        |       ❌        |
| Общие задачи/расходы             |  ✅   |       ✅        |       ⚙️*       |       ❌        |
| Экспорт/удаление дома            |  ✅   |       ❌        |       ❌        |       ❌        |
| Экспорт/удаление своего аккаунта |  ✅   |       ✅        |       ⚙️*       |       ✅        |

`⚙️*` — настраивается owner'ом через `MEMBERSHIP.permissions` (override), по умолчанию выключено для child/ограничено.

## Уровни доступа к ресурсу (SHARE_GRANT.access_level)

- **view** — только чтение.
- **edit** — чтение + изменение содержимого.
- **manage** — edit + управление шарингом этого ресурса.

Грант может быть выдан: всему household, конкретному membership; с `expires_at` (обязателен для guest).

## Модель разрешения (evaluation order)

1. Аутентификация (валидная сессия/токен, MFA при включённом).
2. Определение контекста: `current_user`, его `membership` в `household` ресурса.
3. RLS PostgreSQL отфильтровывает строки, к которым нет доступа (базовый барьер).
4. API-слой проверяет action-level права (роль + `permissions` override + `access_level` гранта).
5. Чувствительность объекта (`sensitivity=high`) может требовать доп. подтверждения/расшифровки.

## Чувствительные категории

- Медицинские данные, документы, удостоверения (`sensitivity: high`): не видны child/guest по умолчанию
  даже при общем шаринге дома — только по явному индивидуальному гранту.

## Отзыв доступа

- Удаление membership / истечение `expires_at` / revoke сессии → немедленная потеря доступа
  (проверяется на каждом запросе; sync-канал перестаёт реплицировать соответствующие строки).

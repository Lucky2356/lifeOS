# Безопасность

Модель радикально изменилась в 1.0: сервера нет, аккаунтов нет, данные не покидают устройство
([ADR 0006](adr/0006-local-only.md)). Значит, и защищать надо другое.

## Что защищаем

Документы, сканы, медицинские записи, финансовые обязательства, семейные дела — то есть данные,
утечка которых бьёт по человеку напрямую. Всё это лежит в одном месте: IndexedDB приложения на
устройстве пользователя.

## Границы доверия

| Граница    | Кто внутри          | Чем защищено                                                                                       |
| ---------- | ------------------- | -------------------------------------------------------------------------------------------------- |
| Устройство | ОС, её пользователь | учётная запись и шифрование диска ОС                                                               |
| Приложение | Life OS             | песочница приложения: на Android — свой uid и приватный каталог, на Windows — профиль пользователя |
| Сеть       | GitHub Releases     | только проверка обновлений; данные пользователя наружу не идут                                     |

Ключевое следствие: **кто получил разблокированное устройство — получил данные.** Приложение не
добавляет собственного пароля, потому что без сервера любой локальный ключ пришлось бы держать
рядом с данными.

## Что делает приложение

- **Определяет тип файлов по содержимому.** `sniffAttachmentMime` читает магические байты и
  сравнивает с allowlist (PDF, JPEG, PNG, WebP, HEIC). Расширение и MIME от системы игнорируются:
  переименованный файл не пройдёт. Лимит — 25 МБ.
- **Не грузит ничего извне.** Шрифты и иконки вшиты в сборку, а не берутся с CDN: приложение
  работает без сети и не сообщает о себе сторонним хостам.
- **Отключает системный авто-бэкап Android** (`allowBackup="false"`, `data_extraction_rules`):
  иначе данные уезжали бы в облако пользователя вопреки обещанию. Перенос — только через явный
  экспорт.
- **Проверяет подпись обновлений.** Установщик десктопа подписан minisign-ключом, и встроенный
  updater Tauri проверяет подпись перед установкой. Android APK подписан релизным ключом.
- **Не показывает чувствительные поля по умолчанию.** Значения объектов с `sensitivity` выше обычной
  раскрываются по явному действию.

## Чего приложение не делает — сознательно

- **Не шифрует данные на устройстве.** Без пароля пользователя ключ шифрования лежал бы там же, где
  шифротекст, — это защита только на вид. Настоящая защита на этом уровне — шифрование диска
  (BitLocker, шифрование Android) и блокировка устройства.
- **Не требует входа.** Разграничение доступа делегировано учётной записи ОС.
- **Не отправляет ничего в аналитику и телеметрию.** Их нет.
- **Не поддерживает совместный доступ.** Разделить данные между людьми без сервера нечем; попытка
  сделать вид, что доступ разграничен, была бы обманом.

## Открытие и сохранение файлов на Android

Чтобы показать приложенный документ в системном просмотрщике или отдать резервную копию в «Поделиться»,
файл сначала записывается во внутренний кэш приложения (он внутри песочницы), а затем передаётся
системе через `FileProvider`. Дальше файл уходит в то приложение, которое выбрал пользователь, — это и
есть смысл действия. Android сам чистит кэш при нехватке места; удаление приложения удаляет его целиком.

Приложение пишет такие файлы в собственный подкаталог кэша и чистит его при каждом запуске: иначе
копия каждого просмотренного скана оставалась бы на устройстве навсегда. Чистим на старте, а не сразу
после «Поделиться», — принимающее приложение читает ссылку не всегда мгновенно.

## Риски и что с ними делать

| Риск                                                     | Последствие                         | Что делать                                                                                      |
| -------------------------------------------------------- | ----------------------------------- | ----------------------------------------------------------------------------------------------- |
| Потеря или сброс устройства                              | данные потеряны безвозвратно        | регулярный экспорт копии (Настройки → Резервная копия) и хранение файла отдельно                |
| Доступ к разблокированному устройству                    | доступ ко всем данным               | блокировка экрана, шифрование диска ОС                                                          |
| Файл резервной копии без пароля                          | JSON читается как есть              | при сохранении задать пароль — копия шифруется AES-256-GCM; без пароля хранить её как документы |
| Установка APK из непроверенного места                    | подмена приложения                  | ставить только APK из [релизов проекта](https://github.com/Lucky2356/lifeOS/releases)           |
| Изменение `appId` / `identifier` при сборке своей версии | существующая база станет недоступна | не менять их; для переноса использовать экспорт/импорт                                          |

## Резервная копия — часть модели безопасности

Единственная копия данных находится на устройстве. Поэтому экспорт (Настройки → «Сохранить копию
всех данных») — не удобство, а обязательная часть эксплуатации: удаление приложения, сброс данных
или потеря устройства означают полную потерю без него.

Файл копии содержит всё, включая вложения. При сохранении можно задать пароль: содержимое
шифруется AES-256-GCM, ключ выводится из пароля PBKDF2-SHA256 (600 000 итераций), проверка
целостности встроена — подменённый файл не расшифруется. Пароль нигде не хранится и не
восстанавливается: забыли — копия бесполезна. Без пароля файл читается как обычный текст,
обращайтесь с ним как с папкой документов.

## Гейты в CI

`.github/workflows/ci.yml` и `codeql.yml` на каждый push и PR:

- `pnpm audit --prod --audit-level=high` — известные уязвимости в зависимостях;
- gitleaks по полной истории — секреты в коммитах;
- CodeQL (`security-and-quality`) для TypeScript;
- `build` / `lint` / `format:check` / `typecheck` / `test` / `validate:content`.

Секрет подписи Android-ключа хранится только в секретах репозитория и попадает на раннер на время
сборки; в коде и истории его нет (`apps/mobile/android/app/build.gradle` читает путь и пароли из
окружения).
